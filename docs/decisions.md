# Architecture Decision Log

Status key: **Approved** = confirmed by the product owner during planning (plan revisions 1–3, 2026-11-22).

| # | Decision | Status | Rationale |
|---|---|---|---|
| ADR-001 | **Real-data core first.** Pass 1 delivers foundation → Claude Code collector → office UI before the QA workspaces. | Approved | Robots must reflect real events; building the data path first avoids mock-driven UI. |
| ADR-002 | **Pass 1 checkpoints 1A → 1B → 1C → 1D.** Each checkpoint has acceptance criteria and stops for review before the next begins. | Approved | Incremental validation; no checkpoint starts until the previous one is demonstrated. |
| ADR-003 | **Electron** for the desktop shell (Pass 1D). | Approved | Tauri would need Rust + MSVC build tools, which this machine doesn't have. Electron offers built-in tray, Windows toasts and DPAPI (`safeStorage`). |
| ADR-004 | **User-level Claude Code hooks**, installed by the app with a backup, merging only its own handlers. | Approved | One install covers every session. The cross-project implication is mitigated by ADR-007 and stated on install. |
| ADR-005 | **Code-drawn pixel sprites** (pixel matrices + palettes rendered to canvas). | Approved | Fully recolorable and no asset licensing. Sprite sheets can be swapped in later. |
| ADR-006 | Data directory **`%LOCALAPPDATA%\QA Virtual Office\`** with a current-user-only NTFS ACL. | Approved | Per-user, non-roaming, local-first. |
| ADR-007 | Default monitoring scope **"Registered projects only"**. The forwarder drops events from unregistered folders *before sending*. | Approved | User-level hooks fire everywhere, so the safest default is to capture nothing outside registered projects. |
| ADR-008 | **Metadata-only capture by default.** Prompts, tool inputs, tool outputs, notification text and transcripts are never collected unless explicitly opted in; opted-in content is redacted and truncated. | Approved | Privacy is mandatory, and org policy forbids customer PII in data provided to Claude. |
| ADR-009 | **Forwarder-side project resolution.** The cwd never leaves the hook process: only a `projectId` (or opaque HMAC folder keys in All-sessions scope) is sent. Users choose a safe display alias. | Approved | Even home-masked paths reveal folder names. |
| ADR-010 | **Async `command` hooks only** (never `http` hooks). The forwarder always exits 0 and the collector always replies `204` with an empty body. | Approved | HTTP hooks are synchronous, so a hung collector would stall Claude. This way the app can't block, approve or deny anything. |
| ADR-011 | **One-time launch-token cookie authentication** for the UI and API (implemented in Pass 1B). | Approved | Stops other local web pages and processes from reading QA data through the API. |
| ADR-012 | **Synthetic E2E fixtures isolated from the production DB**: they're used only in automated tests and in a separate `demo.db`. | Approved | Production monitoring must never mix real and mock data. |
| ADR-013 | Forked sessions get a **new session and robot identity**. Resumed sessions keep theirs. A parent link is stored only if the payload actually carries one. | Approved | Concurrent forks must be represented independently, and nothing is inferred. |
| ADR-014 | Stack: npm workspaces, TypeScript, Fastify + `@fastify/websocket`, better-sqlite3 with plain-SQL migrations, React + Vite, Vitest. | Approved (rev 1) | Minimal dependencies that are well supported on Windows and Node 24. |

## Pass 1B decisions (within the approved scope)

| # | Decision | Rationale |
|---|---|---|
| ADR-015 | The forwarder spools **already-sanitized** events only (never raw stdin) to `spool.jsonl` (5 MB cap) on connection errors and 5xx/429; 4xx rejections are not spooled. The server claims the file by renaming it, applies events in timestamp order and relies on the event id for exactly-once. | Nothing is lost while the server is down and the privacy guarantees hold on disk. |
| ADR-016 | A replayed event **older than the session's latest state is recorded but not applied** ("stale"); replay never raises notifications. | Replay must never rewind a live status or raise stale alerts. |
| ADR-017 | Registered and excluded project paths are masked as `<project>` inside opted-in content, in the forwarder. | Users can type a project's path into a prompt; opt-in content must not reintroduce paths. |
| ADR-018 | The status line is opt-in, **wraps** an existing one and restores it exactly; it forwards numbers only. | Usage figures come only from what Claude Code reports; the user's own status line must keep working. |
| ADR-019 | Backups are single files (non-WAL) verified with `integrity_check`; a database failing `quick_check` is moved aside (never deleted) and the newest valid backup restored. | Self-contained backups; no silent data loss on corruption. |
| ADR-020 | Enabling content capture or "All sessions" scope needs explicit confirmation in the API (not only the UI). | The privacy-widening choices cannot be flipped by an accidental request. |

## Pass 1C decisions (within the approved scope)

| # | Decision | Rationale |
|---|---|---|
| ADR-021 | Sprites are **pure functions** of (type, status, palette, frame) producing pixel grids; the canvas only paints them. The shared animation clock advances the frame index, never the status. | Robots can only show real status changes (C2), and animations are testable by measuring pixels (C1) without a browser. |
| ADR-022 | A robot's **appearance** (one of 7 types) and its **logical role** are separate fields. The role decides the department and station; nothing assigns roles automatically. New robots default to QA Analyst. | The spec asks for customizable looks and logical roles, and Claude Code has no native specialised agents. |
| ADR-023 | Robot STATE is derived from sessions (real events); robot records carry identity only. Robots idle for more than 24 hours are hidden unless requested. | Avoids duplicating state and keeps the floor uncluttered without deleting identity. |
| ADR-024 | Every KPI is computed from real records or shows **"No data yet"** with the pass that delivers it. "Active" means not ended and seen in the last 30 minutes; each real KPI carries its formula. | No invented metrics, and percentages are never shown without a denominator. |
| ADR-025 | No router, state or UI library: a 20-line hash router and one React context. Pixel font bundling deferred (system monospace headings). | Fewer dependencies; the plan's React Router/TanStack Query/Zustand added nothing needed yet. |
| ADR-026 | On narrow screens the pixel floor is replaced by compact status cards. | The spec prioritizes information over decoration on mobile. |

## Pass 1D decisions

| # | Decision | Rationale |
|---|---|---|
| ADR-027 | **The desktop app runs the server as a child process on the system Node** and **attaches** to a server that is already running (never replacing or killing it). The server it started is stopped when the app quits. *Approved by the product owner after the blocker was explained.* | The native SQLite module is built for Node, not Electron; one build cannot serve both. The packaged installer (Pass 5) must bundle a Node runtime. |
| ADR-028 | The desktop launcher clears `ELECTRON_RUN_AS_NODE`. | VS Code sets it for child processes, which turns Electron into plain Node. |
| ADR-029 | Toasts and the tray badge come from the same real-time event stream as the UI; toast text is built server-side from metadata only. Default toasts: High and Warning priorities; the user chooses. Alerts never approve or deny anything. | Permission requests must get immediate attention without bypassing Claude Code permissions. |
| ADR-030 | The UI may only talk to the local server: the Electron session cancels every request to another origin, denies every permission and blocks navigation and `window.open`. | Defence in depth beyond the CSP. |
| ADR-031 | A test seam exists only when `QAVO_E2E=1` is set: read-only state plus a toast-click simulator on a main-process global, unreachable from the page. | Tray state and OS toast clicks cannot otherwise be observed or driven by automation. |

## Pass 2 decisions

| # | Decision | Rationale |
|---|---|---|
| ADR-032 | **Pass 2 is split into 2A requirements + test cases, 2B execution + evidence, 2C defects + exploratory + task board, 2D agent integration (MCP).** Each checkpoint is validated and reported before the next. *Approved by the product owner.* | Same incremental discipline as Pass 1. |
| ADR-033 | **Only a signed-in human can approve or reject test cases, mark tests PASSED or close defects.** Every QA service function takes an `actor` (human / agent / system) and enforces this itself; the database backs it with a CHECK constraint (an approval can only be recorded as made by a human). HTTP routes under `/api` are always the human actor; agents will use separate, limited routes with their own token (2D). *Approved by the product owner.* | An AI agent must never be able to certify its own work. Enforcing it in the service and the database means no route or UI bug can bypass it. |
| ADR-034 | History tables are **append-only** (triggers) and QA tables reference projects with **RESTRICT**: a project with QA records cannot be removed, only archived. | Audit trail and no silent loss of test assets. |
| ADR-035 | Ambiguity checks are **deterministic word lists, not AI**, raise flags for human review (never verdicts), and never re-raise a dismissed hint. Requirement import is a deterministic parser with a preview. | Predictable, testable and honest about what it can detect. AI assistance comes through the human-supervised agent path in 2D. |
| ADR-036 | Coverage is always shown with numerator, denominator and formula; with a zero denominator it shows "—". A test case's execution status is NOT RUN until executions exist (2B). | No invented or misleading quality figures. |
| ADR-037 | **Execution results are per test run, and figures use the latest finished result per approved test case.** A run starts from approved cases only and records the test case version; a closed run is immutable. PASSED can only be recorded by a human (service + DB constraint); an agent may only start a test or report FAILED/BLOCKED with a note. FAILED/BLOCKED/SKIPPED and re-testing need a note. | Honest, non-double-counted figures and an audit trail; an agent can never certify a pass. |
| ADR-038 | **Evidence is stored as files in the data directory under random names, never in the database.** Allowed types are checked by extension and signature; text is redacted before saving; downloads are attachments with nosniff. Images/PDFs are not redacted (stated in the UI). Evidence is excluded from exports and backups for now. | Keeps sensitive artifacts local and out of anything that leaves the machine; limits what a hostile file can do. |
| ADR-039 | **A NULL result in a SQLite CHECK passes.** Human-only constraints are written with COALESCE and, for the 2A `test_cases` CHECK that could not be altered, backed by triggers (migration 004). | Fixes a real hole found while writing 2B; the DB now really enforces the rule. |
| ADR-040 | **Defect status changes are human decisions.** Every transition is human-only (service + DB CHECK on CLOSED/REJECTED/DUPLICATE); agents may report defects and comment, and edit only their own NEW defect. Rejecting, duplicate, reopening and closing need a note. A defect can be raised from a failed test execution (pre-filled, linked). | An AI agent must never close its own bug reports; the history explains each decision. |
| ADR-041 | **The task board has six stages and never auto-assigns.** Only a person completes a task (service + DB CHECK); blocking and reopening need a reason. The sidebar Task Board opens the Manual QA board. | Assignment and sign-off stay with the team. |
| ADR-042 | **Demo mode is a separate, disposable world.** `npm run demo` starts a second server on port 47822 with its own data folder (`%LOCALAPPDATA%\QA Virtual Office Demo`), rebuilt from scratch on every start. Robots come from synthetic hook events through the real status machine; QA records come through the real services. The UI shows a permanent DEMO DATA pill and banner; the server refuses to install or remove hooks or the status line (and its settings path points inside the demo folder), refuses the real data directory and the real port. | Lets the office be previewed or demonstrated without Claude Code, with no way for fake data to mix with real data or to alter the real Claude settings. |
| ADR-043 | **Agents act through one narrow, token-authenticated surface (`/api/agent/*`) used by a local stdio MCP server.** The tool list and every rule live in the server; the MCP bundle is a thin proxy and is not trusted. Tools are allow-listed, address projects by alias and entities by code, take strict schemas that cannot express forbidden values, and run as the `agent` actor. | One place to review and test what an agent can do; no path or id leaks; a compromised or modified MCP file gains nothing the server would not already allow. |
| ADR-044 | **Agent access is off by default, needs a person's confirmation, uses its own revocable token, and every call is audited without content.** The agent token is separate from the hook token and the UI cookie and opens nothing else; the app never edits Claude Code's configuration (the person runs the shown `claude mcp add` command). | The person stays in control and can see and stop what agents do. |
| ADR-045 | **Everything an agent reads is redacted again on output.** | Test data typed by people may contain personal data; agents (and the model provider) should never receive it. |
| ADR-046 | **"Launch Claude Code here" is a confirmed, fixed command (console window in the project folder running `claude`)** with no user text in the command; folder names containing characters a terminal could misread are refused. | Convenience without an injection path. |
| ADR-047 | **The lounge shows robots whose real status is Idle or Completed, and nothing else.** Robots working, waiting for the person, failed or disconnected stay at their desks. The furniture a robot uses is a stable cosmetic pick from its id; the furniture animates, the robot's placement never does on its own. Robots appear in the lounge in place (no walking). | Gives idle robots a place to rest without ever inventing activity; keeps attention-grabbing states where the person looks. |
| ADR-048 | **Pass V (office world) is approved as V1 building and camera, V2 life, V3 atmosphere, with V4a (raised hand) shipping in V2 and V4b (approve/deny from the office) NOT approved yet.** V1: one tile-map building (lobby, hallway, a room per project, lounge); robots walk only when a real status change moves their target; arrivals use the elevator; the classic floor stays available. The model (map, pathfinding, camera, scene) is pure and tested; the canvas is a thin renderer; a hidden list mirrors robots for accessibility and tests. | Delivers the Habblaud-style office while keeping our rules: metadata-only capture, robots reflect real events only, nothing moves on its own. |
| ADR-049 | **V2 adds life without adding data.** Activity bubbles use only the tool name and the file/command category already derived locally by the forwarder (the session DTO gains a `current tool` of exactly those fields). Walls get depth and per-room trim; room doors open for nearby walkers and the elevator for arrivals. Celebrations (confetti on completed, rain on failed), the hourglass, alert badges (V4a) and drones are all derived from real status changes; effects use a seeded generator and the scene clock, never randomness or the wall clock. Lounge furniture grows to five kinds (couch, coffee, arcade, TV, ping-pong). | Richer, Habblaud-style presentation within the privacy rules: metadata-only capture, robots reflect real events only. |
| ADR-050 | **V3 atmosphere is a per-viewer, local preference with safe defaults.** Day/night follows the viewer's local clock (fixed sunrise/sunset, no location), seasonal themes are automatic by date or chosen, and sounds are synthesized in the browser and OFF by default, played only for real events (arrival, finished, failed, needs you), rate-limited and capped quiet. Preferences live in localStorage, are validated on read and are never sent anywhere. **Database recovery now only treats genuine corruption as corruption**: a lock or permission error is retried and reported with every file untouched. | Keeps the Habblaud-style polish within the privacy rules, and fixes a data-safety flaw (a temporary file lock could have caused a healthy database to be replaced by an older backup) found while chasing a flaky test. |
| ADR-051 | **V4b: approving permission requests from the office is an opt-in, human-only, fail-silent bridge.** One synchronous hook on `PermissionRequest` only (installed by the person with a plan and acknowledgement); it prints a decision only after the signed-in person decided, otherwise nothing and exit 0 so Claude Code's normal prompt stays; registered projects only; allow is offered only when the details are shown (tool-input capture on) while deny is always possible; decisions are final, single-use and erased of any command text; the hook and agent tokens can never decide; no permanent allow rules. A crash-on-exit found by the end-to-end test (Windows exit code 0xC0000409 after talking to the real server) was fixed by closing connections and not calling `process.exit`. | Delivers the Habblaud-style "answer from the office" feature without ever letting a tool, an agent or a bug approve something a person did not see and choose. |
| ADR-052 | **Test cases can be imported from a Markdown table or a spreadsheet paste, as human-authored drafts only.** Columns follow the team's template; execution, defect, evidence and automation columns are never imported (a result only counts when a person records it). Re-import skips existing Test Case IDs (new additive column `external_id`, migration 008). Unknown type/priority use documented defaults with a visible warning; nothing is interpreted by AI. | Lets the team bring existing test cases in without weakening the rules: approval, execution and results stay human steps, and re-importing never overwrites reviewed work. |
| ADR-053 | **Agents work through named playbooks; a reviewer is never the writer, enforced by identity (Pass P).** Roles, fixed tool allow-lists, steps and review checklists live in code; the person can rename agents (unique names) and add house rules but can never widen tools. Roster: Ada, Quinn/Rhea, Axel/Vera, Piper/Cole, Bram, Lena. Later checkpoints add per-run credentials (hashed, short-lived, bound to a role), attribution of drafts, and review recommendations that never change status. Approval, results and closing stay human-only. | Makes it clear who wrote and who reviewed each item, keeps review independent, and keeps the person as the only decision maker. |
| ADR-054 | **A launched agent has a server-enforced identity (P2) and its own robot in the office (P4).** Run credentials are random, hashed at rest, bound to one playbook, agent name and project, valid for 8 hours and revocable; they live only in a per-run MCP config file under the data folder's ACL, which is removed on stop or on the next launch. The server checks the role's tool allow-list and the project on every call, records the drafter's name, and never falls back to the shared token when a run credential is bad. Claude is launched with fixed arguments and a run id in the environment; the forwarder passes that random id (never content) so the server can name the session's robot. | Makes who-wrote-what real and prepares writer-is-not-reviewer enforcement, without trusting a prompt, and without putting user text in a command line. |
| ADR-055 | **Reviews are append-only recommendations by a different named agent; the writer-is-not-reviewer rule is enforced by the database.** A review is bound to the launched run, records a fingerprint of the content it reviewed (an edit makes it outdated), is redacted and capped, and never changes a test case's status or counts as approval. Drafters keep their name as history, so renaming cannot make a reviewer the writer. Not a gate: the person may approve regardless. Agent writes now refresh open pages. | Gives the person independent, attributable second opinions without letting any agent decide, and keeps the rule intact even if the service has a bug. |
| ADR-056 | **The writer can answer the reviewer (P3b).** A named writer lists its own sent-back drafts and may attach a short, redacted reply to its edit (or send one alone); it is stored in the append-only history under its name and shown to the reviewer and the person. A reply is not an edit and never changes a review. | Closes the loop between writer and reviewer without giving either a decision, and keeps the explanation next to the work. |
| ADR-057 | **Old, unnamed agent drafts are handed to a named writer by a person, never automatically.** A human-only action records the new drafter in the append-only history; it is refused for anything that is not an unnamed agent draft still in Draft, for non-writer roles, and for an agent that has reviewed the case. The writer's list says when drafts that need changes are not hers, so she does not recreate them. | Found when a writer, unable to touch old drafts, wrote duplicates. Keeps "a named agent edits only its own drafts" and "a reviewer is not the writer" intact while letting the person move old work forward. |
| ADR-058 | **The agents have desks in a QA Team room; a person can retire old robots.** One desk and name plate per role, in roster order; a robot appears at its desk only while it has a real session, so empty desks stay empty and nothing moves without an event. Retiring hides a robot without deleting it, is refused while it looks alive (10 minutes) and for agents' robots, and undoes itself if the session becomes active. | Puts the whole team in the office without inventing activity, and gives a way to clean up the robots of old sessions. |

## Notes recorded during Pass 1A

- **npm 11 `allowScripts`.** Install scripts are allowed only for `better-sqlite3` (prebuilt native binary) and `esbuild` (platform binary). They're recorded in the root `package.json`.
- **Symlinks.** Creating a directory symlink needs a privilege this account doesn't have (EPERM), so that test skips and reports. Junctions (`mklink /J`) work and are tested in both directions.
