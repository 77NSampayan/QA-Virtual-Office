# Pass 2D: Validation Results (2026-11-22)

**What 2D delivers:**
- **A local MCP server, `qa-office`** (stdio), so a Claude Code agent can work as a QA assistant with **limited rights**: read QA data and create *drafts*. 17 tools: list projects, summary, list/create requirements and flags, list/get/create/edit-own-draft test cases, list/report/comment defects, record "started / failed / blocked" on a test (never passed), add an evidence note, add exploratory notes, create/move tasks.
- **Settings → Agent access (MCP):** off by default; a person turns it on (after a confirmation), sees the one-line setup command, a log of what agents did, and can revoke the token.
- **"Launch Claude Code here"** on each Project Room: after a confirmation, opens a terminal in the project folder running `claude`.
- Project Rooms now show **real Manual QA figures** (they still said "Arrives in Pass 2").

**Automated:** `npm test` → 32 files, **542 passed, 1 skipped**. `npm run e2e` → 8 files, **90 passed** (8 new for 2D). Typecheck and lint clean.

| # | Acceptance criterion | Result | Evidence |
|---|---|---|---|
| 2D-1 | **An agent can never approve, pass, close, reject, complete, archive or delete** | **Pass** | Those tools do not exist (unknown names return 404; tests try `qa_approve_test_case`, `qa_close_defect`, `qa_complete_task`, `qa_delete_requirement`, `qa_mark_passed`). The tool schemas cannot even express the forbidden values: the result tool accepts only `in_progress`, `failed`, `blocked`; the task tool has no `completed`; `passed`, `skipped`, `completed`, `status: approved/closed`, `assignee` and unknown fields are all refused with 400. Underneath, the 2A–2C services and database constraints refuse the agent actor anyway. Through the real bundled MCP server over stdio, the same refusals come back as tool errors |
| 2D-2 | Agent access is opt-in, separate and revocable | **Pass** | OFF by default (every call is refused and the refusal audited); only a person (cookie + CSRF header + explicit confirmation) can turn it on, and the agent token cannot turn itself on; a **separate 256-bit agent token** (not the hook token) in `agent-token` under the current-user-only ACL; "Revoke and replace" kills the old token at once, and the running MCP server picks up the new one (it re-reads the file on every call) |
| 2D-3 | The agent token opens nothing else | **Pass** | It is refused on the UI API, the hook route, the launch route and settings (401); browser requests (any `Origin`) and foreign hosts are refused; the hook token does not work on agent routes; its own small rate limit |
| 2D-4 | Agents see no paths, no ids, and only redacted text | **Pass** | Projects are addressed by safe alias and entities by code (TC-0001, DEF-001, TSK-001…); `qa_list_projects` returns alias/description/type only; everything an agent reads passes through the redactor again (test: an email, phone number, card number and API key typed by a person never reach the agent); text agents write is redacted by the services before storage |
| 2D-5 | Agent work is labelled and reviewable | **Pass** | Agent requirements, drafts, defects, tasks, notes and results carry `agent` as author/reporter and show an "agent" pill; a test result by an agent is recorded as *agent assisted*; an agent can edit only a draft it created, and not once a person submitted it for review; an agent-reported defect starts as NEW |
| 2D-6 | Auditable without recording content | **Pass** | Every call (including refused ones) writes one row: tool, project, outcome, error code: never arguments, titles or results (test with marker strings); the table is append-only; the last 50 calls show in Settings |
| 2D-7 | MCP protocol conformance (stdio) | **Pass** | `initialize` negotiates a supported version (2025-06-18, 2025-03-26, 2024-11-05) and announces only the tools capability; notifications get no reply; unknown methods return -32601; tool failures are `isError` results, not crashes; odd tool names are rejected before anything is sent; stdout carries only JSON-RPC; clean exit when stdin closes; "access off" and "app not running" give clear messages. The test starts the **real bundle as a child process** against a live server |
| 2D-8 | "Launch Claude Code here" is safe | **Pass** | Needs a confirmation; only registered, non-archived projects whose folder still exists; the command is fixed (a console window in that folder running `claude`), no user text is placed in it; a folder name containing `% ^ & \| < > " !` is refused (a terminal could misread it); demo mode refuses; only the signed-in UI can trigger it (the agent token cannot). The test replaces the real launch with a recorder, so no window opens during tests |
| 2D-9 | Setup is explicit, nothing is changed for you | **Pass** | The app never edits your Claude Code configuration: Settings shows the exact `claude mcp add --scope user qa-office …` command (and the remove command) for you to run once. It contains file paths, so it is a protected request (CSRF header) and never contains a token |
| 2D-10 | Real figures in Project Rooms | **Pass** | The Project Room shows test cases, latest results, open defects and open tasks for that project (with "No test has been executed yet" etc. when empty); the old "Arrives in Pass 2" placeholders are gone (Automation still says Pass 3) |

## Not done / open

- **Not tested with a live Claude Code session in this environment.** The MCP server is tested over the real stdio protocol with a scripted client, but registering it in your Claude Code (`claude mcp add …`) and watching an agent use it is a step for you. Claude Code's exact `mcp add` syntax can differ between versions; the remove command and `claude mcp list` are the quickest checks.
- **Same-user limitation (documented):** any process running as your Windows user can read `agent-token`. The token stops other users, browsers and remote hosts, not malware running as you. Turning access off blocks everything regardless of the token.
- Agents cannot attach screenshots or files (notes only), and cannot start or complete exploratory sessions, create test runs or close anything.
- The MCP file is copied into the data folder when the server starts (`npm run build` first); the Windows installer (Pass 5) will bundle it.
- `Launch Claude Code here` uses `cmd.exe`/`claude` on the PATH; the Windows Terminal profile is not used.
